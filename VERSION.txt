【v1.3.1 相对 v1.3.0 的变化】
本次是**质量加固版**：把两处"报告说标了、标注版上却没有 / 编号对不上"的问题从全量
44 份标注版里挖出来并修掉，同时补上两道机器闸门，防止同类问题再悄悄发生。

新增（会话安全；看板按角色；重复项目合并与对比；模型固化；提交侧两项；界面调整；两道闸门 + 一个核查工具）
· **登录会话机制重做**（用户反馈："没有退出机制，下次不管多久打开网址就直接登录到原来的用户了"）
  · 查下来属实且更严重：**服务端根本不校验会话时间** —— "7 天过期"只在**登录那一刻**清理一次，
    Cookie 又写死 `Max-Age=7 天`。等于关掉浏览器过几天回来还是登录状态，
    而**偷到 sid 的人更是永久有效**（服务端从不看时间）
  · 现在两道一起管：① 浏览器端改成**会话 Cookie**（不写 Max-Age）→ **关浏览器即失效**；
    ② 服务端每次请求都校验：**空闲 12 小时**过期 + 绝对上限 7 天（可配 WB_SESSION_IDLE_MS / WB_SESSION_MAX_MS）
  · 过期时顺手清掉浏览器里的废 Cookie，前端收到 401 就重新登录
  · ⚠️ 顺手堵掉的低级安全问题（都写进了 `test-security.mjs` 的断言，防止改回去）：
    - **建号不校验密码长度**（只有"改密码"接口校验）→ 管理员能建出 1 位密码；现在建号/重置/自行改密三处口径一致
    - 账号不存在时跳过哈希比对 → **响应时间可枚举账号**；现在无论存在与否都跑一次同样代价的比对
    - Cookie 解析遇坏编码会**抛异常把请求打成 500** → 改为容错解析
    - 静态服务用 `startsWith(PUBLIC_DIR)` 判目录穿越（`..\public-evil\x` 也能过）→ 改为 `path.relative` 判定 + 只服务白名单后缀
    - 暂存 ID 未校验格式就拼路径 → 加 `^[A-Za-z0-9_-]{6,40}$`
    - 统一加 `X-Content-Type-Options: nosniff` / `Referrer-Policy` / `X-Frame-Options`
  · 实测确认没问题的（不是漏洞）：退出按钮存在且服务端删会话、密码走 scrypt+每账号盐+timingSafeEqual、
    登录失败提示统一不泄露账号是否存在、限流/阶梯验证码/锁定/IP 封禁齐全、写操作都是 POST + SameSite=Lax、任务 ID 穿不出目录
· **数据看板按角色收敛**（用户反馈：审核专家看到的费用/token 不该显示；同一数字重复三遍）
  · **费用与 token 一律只给管理员**：`已取消（未花费）`、token 合计、缓存命中率、闲时调用占比、
    使用人数、按使用人表的 token/缓存/费用列、按日提交的每日 ¥、省钱效果面板 —— 审核专家统统不看
  · 审核专家保留：审了多少份、进行中/待确认重复/失败/已取消、闲时/忙时**次数**占比、按使用人（次数口径）、
    按日提交（次数）、问题分布、项目台账
  · **去重**：`78.3%` 原本在一屏里出现三遍（KPI + 饼图图例 + 右侧面板），且 KPI 的 token 合计与面板里
    "范围内 token"**口径不同却并排**（16495.1K vs 16943K）→ KPI 不再重复占比、右侧重复面板取消
  · 实测（影子实例三个身份截图）：管理员 ¥ 出现 11 处、审核专家 **0 处**、普通用户 **0 处**；
    普通用户看不到「按使用人」表（用户截图里的黄框内容）
· **同一项目重复审核：台账合并显示 + 与上次逐条对比**（用户要求）
  · 台账新增「**逐条 / 按项目**」切换：**按项目**把同一项目的多次审核合成一条（不分提交人 —— 用户指定），
    显示提交次数、参与人、最近一次、累计 P0/P1；点「展开」看每次的**提交时间/完成时间/提交人/状态/问题数**与**与上次对比**

    并在**审核结论处着重提醒未响应的高级别问题**（P0 红字、P1 橙字）；校对成果只列校对类条目
  · 落盘 `run/compare.json`，摘要写进任务元数据（台账直接读，不必再算）；没有上一轮时**不出现这一节、不留空框**
  · 触发时多一次 API 调用（只有"同项目再次审核"才发生）；实测：3 条进 3 条出、编号不飘、1 秒完成

· **★ 审核模型固化到 `deepseek-flash`**（用户纠正的严重问题）
  · 事故：我先把流水线里硬编码的模型名改成"读设置里的模型名"，而设置默认值是老别名 **`deepseek-chat`**
    → **审核悄悄换档**（用户当天发现："这里不换，固化"）
  · 现在口径（`auditModelName()` 唯一口径）：**DeepSeek 家固定 `deepseek-flash`**，设置里那一栏不生效；
    **切到智谱/百炼/Kimi/自定义时**才用设置里的模型名（否则把 deepseek 的模型名发给别家会直接报错）
  · 界面同步：DeepSeek 家模型名输入框**置灰并写明"固定 deepseek-flash"**；默认配置值也改成 deepseek-flash
  · **启动日志新增一行 `审核模型 : …`**（并注明固定/取设置），从根上避免"界面写 A、实际跑 B"的误判
  · 实测事实（1 token 调用）：DeepSeek 官方只认 `deepseek-flash` 与 `deepseek-v4-pro`；
    传 `deepseek-v4.1-flash` 被 **HTTP 400** 拒绝（"The supported API model names are …"），
    `deepseek-v4-flash` 只是落到 `deepseek-flash` —— 这个事实写进了 providers.mjs 的注释与自检

· **★ 修复 BUG：改了账号的登录 IP，人却还是进不来（两道闸门不联动）**（2026-09-28 用户报障）
  · 用户原话："我给张超宇的登陆IP修改为10.81.109.214后，他还是无法访问……就是说修改IP和白名单并没有联动，需要你优化这个功能。"
  · **根因**：全局白名单是**登录前**判定的（那时还不知道是谁），而它原来**只看管理员手工那份名单**。
    于是把某人的绑定改成新 IP 后，他在"登录前"那一关就被挡住 —— **"每账号绑定"根本没机会生效**；

    · 账号绑定列表按 2 秒缓存（每请求读一次 users.json 不值得，但改完要立刻生效）。
    · **边界（刻意保留、向后兼容）**：**手工白名单为空时仍然"不限制"** ——
      否则"只想给几个人绑 IP、不打算开全局限制"的系统会被这个联动突然锁死。

    **PowerPoint 渲染出 391 字、LibreOffice 只渲染出 27 字** —— 正文整段丢失，只剩右侧"一字一行"的零碎残字
    （如 `E` / `（Ja` / `量的`）。标注的定位与画框都建立在这个渲染结果上，**正文都不在页面上，框自然"错位"**。
    · 本机确认装有 PowerPoint（`C:\Program Files\Microsoft Office\root\Office16\POWERPNT.EXE`），
      实测 PowerPoint COM 在**登录用户身份下可用**（转换忠实），但在**服务身份（SYSTEM / session 0）下打不开文件**
      （COM 能创建、`Presentations.Open` 返回空）—— 所以不能靠 COM 解决。
    · **有效且零依赖的修法**：转换前把副本里的 `<a:spAutoFit/>` 换成 `<a:noAutofit/>`（用 PowerShell 的
      `System.IO.Compression.ZipFile` 就地改那几个 XML 部件）。实测同一页从 27 字 → **412 字**，正文完整、版面正常；
      该任务整份标注的**精确定位率从 45% 提升到 75%**（可用率 70% → 85%）——因为引文现在真的能在页面上找到了。
    · **只改副本、绝不动用户原件**（原件要留档、要能下载）；修补失败自动退回原件并记一条日志，不让任务失败。
  · **第 2 条的实现**：新增"PPT 那一路"标注版（配对任务里有 PPT 才做）：
    - 文件：`原PPT标注版-校对.pdf` / `原PPT标注版-审核.pdf`（报告那一路文件名不变）；
    - 分路 key：报告 `proof`/`deep`，PPT `ppt-proof`/`ppt-deep`（状态文件、失败记录、统计都按 key 落盘）；
    - 流水线 `⑤.5`：检测到"报告 + PPT"配对（`hasPairedPpt`）就**同时生成 PPT 两档**（校对 + 审核）；
    - 接口：`/annotate`、`/annotated.pdf` 支持 `kind=ppt`；没有配对 PPT 的任务请求 PPT 那一路会被**明确拒绝**

    - 界面：有配对 PPT 时才多出「原PPT标注版（校对）」「原PPT标注版（审核）」两个按钮，失败提示覆盖这两路。

· **★ 修复"标注版要点了才生成、点了还等很久"**（2026-09-28 用户反馈，实测是环境故障）
  · 用户原话："功能完善：标注版直接生成，不需要等点击了再生成，这样太慢。"
  · **排查结论：不是"没做自动生成"，而是自动生成一直在失败。** 流水线 `runTask ⑤.5` 早就写着
    "审核时就把校对版/审核版两份标注版生成好（点开即下）"，日志里也能看到它每轮都执行了 ——
    但每一轮都以 `spawn pdftoppm ENOENT` 失败，只在服务器日志里留一行 ERROR，界面完全看不出来。
  · **根因**：`pdftoppm` / `pdftotext` 原来写的是**裸名字**，靠 PATH 找。开发时（管理员用户身份跑）
    能找到 —— 它们装在 `Administrator` 的**用户级 PATH** 里（MikTeX 的 bin）；
    而**生产服务是计划任务以 SYSTEM 身份运行**（`LogonType: ServiceAccount`），只看得到**机器级 PATH**，
    里面那个目录不存在 → 每次 spawn 都 ENOENT → **30 个已完成任务里有 7 个没有标注版**，
    同事点击后前端每 6 秒重试一次、每次都失败 —— 感受就是"点了还要等，等了还是不出来"。
    顺带发现 `.doc` 走的 `soffice` 有**并发冲突**（LibreOffice 单实例，同一个用户配置目录只允许一个进程），
    6 个任务并发时也会失败。
  · **修法（都已落地）**：
    1. `annotate.mjs` 新增 `findExe()`：**解析成绝对路径**（env 覆盖 → PATH → 常见安装位置 → 扫 `C:\Users\*\scoop\apps`），
       `toolchainStatus()` / `toolchainHint()` 给出体检结果与**可执行的修复指引**；
       找不到时不再退化成裸名字，而是抛中文错误「找不到 pdftoppm：请安装或设 PDFTOPPM=<绝对路径>」。
    2. `soffice` 每次转换用**独立的 `-env:UserInstallation` 配置目录**（用完删除）→ 并发不再互相打架。
    3. **启动横幅新增 `标注工具 : ✓/✗` 一行** —— 这类故障以后开机就能看见（这次就是没人看见那行 ERROR）。
    4. **失败不再静默**：流水线把失败原因写进任务元数据 `annotateError`（含修复提示），
       任务详情接口下发它，界面在按钮旁直接显示「⚠️ 标注版（校对版）上次生成失败：… 修复提示：…」，
       按钮变成「重试生成」。
    5. **不再空转重试**：服务端只在"从没生成过"或**用户明确点重试**（`retry:true`）时才起新任务；
       前端轮询不再把一个必然失败的转换每几秒重跑一遍。
  · **已修复生产数据**：新增常备工具 `运维/fix-annotate.mjs`（默认 `--dry` 只列不给改），
    用它给受影响的 7 个任务补出 **14 份标注版**（校对版 + 审核版），全部成功：
    单份 12~18 秒、定位率 67.7%~87.5%、10~17MB。补完后任务详情 `annotateReady.proof/deep` 均为 true，
    HTTP 下载实测 200 + `application/pdf` + 合法 PDF 头。
  · **验证**：自检 `engine/test-annotate.mjs` 从 93 项扩到 **113 项**（新增 20 项专测这次事故：
    三个工具必须解析成**存在的绝对路径**、源码里不许再出现裸名字写法、soffice 必须带独立配置目录、
    启动横幅必须报工具链、失败原因必须落盘并下发、只有显式重试才重起）；
    另做两项实机验证：① 生产（SYSTEM 身份）重启后横幅自己打印出
    `标注工具 : ✓ soffice + pdftoppm + pdftotext 都在`；② 把 PATH 砍成只剩 `C:\Windows\System32`
    （模拟 SYSTEM 环境）仍能解析到三者 —— 证明修复不依赖运行身份。
  · 教训（写进代码注释与文档）：**凡是依赖外部程序的功能，路径必须显式解析并在启动时体检**；
    "开发机能跑"不等于"服务能跑"，两者的运行身份/PATH 可能完全不同。

· **IP 访问控制（防止其他部门访问与调用）**（2026-09-28 用户要求，已用真实名单上线）
  · 用户原话："在用户管理的位置增加 IP 或 MAC 地址绑定，防止其他部门访问和调用。"
  · ⚠️ **MAC 不做拦截，只记录**（已向用户说明并被接受）：浏览器/网页**读不到** MAC，只能靠服务器查本机
    ARP 缓存；ARP 表几分钟就老化（不常访问就取不到 → 误拦自己人）；MAC 在网卡属性里**随手可改**；
    且只在**同一网段**内有，跨网段取不到。所以它只作为"核对是不是本人那台机器"的辅助信息，
    登录时记录一次（按 IP 缓存 10 分钟，避免每个请求起进程）。
  · **做的是 IP 两道闸门**（用户选定）：
    ① **全局白名单**：名单外的 IP **连登录页都进不去**（挡其他部门的主力）——静态页与所有 API 都判，
       被拦时给出**可读 HTML 页面并显示他的本机 IP**（方便同事报给管理员）；

    精确 `10.81.108.77`、整段通配 `10.81.108.*`、网段 `10.81.108.0/24`，空列表＝不限制。
