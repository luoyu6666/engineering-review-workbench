# 源码注释规范（本项目统一口径）

> 适用范围：`web/`、`engine/`、`运维/`、`bench/` 下的 `.mjs` / `.js` / `.cjs` / `.ps1` / `.html`(内联 JS/CSS) / `.py`。
> 目标：注释读起来像**工程代码**，不像对话、不像说明文；只保留对维护有用的信息。

## 一、硬性禁则（机检会报错）

| 类别 | 禁止 | 改为 |
|---|---|---|
| 表情与符号 | `⚠️ ★ ✅ ❌ ⛔ ✗ ✓` 等 | 省略，或用标签 `NOTE:` / `WARN:` / `FIXME:` |
| Markdown 标记 | 注释里出现 `**粗体**`、`> 引用`、`- 列表` | 纯文本；需要分点用 `·` 或直接分行 |
| 开发过程叙事 | 踩过、踩到、白折腾、翻车、坑（泛用）、越看越糊涂、一句话、说白了、反正、干脆、顺手、白干、假装、没人、谁也不知道 | 直接陈述**事实与约束**：早期实现的问题用"此前…，导致…" |
| 归因口吻 | 用户要求 / 用户报的 BUG / 用户反馈 / 按用户 x 月 x 日要求 / 同事 | 中性事实：`2026-09-28: 生效白名单改为手工白名单 ∪ 账号绑定 IP`；指代使用方时写"使用方/调用方/客户端" |
| 第一人称 | 我 / 我们 / 咱们 | 本服务 / 本模块 / 调用方 |
| 情绪与夸张 | ！！、非常、极其、严重（非安全等级）、"值得记住" | 量化或删除：`单次耗时约 1.2s`、`会导致登录失败` |

## 二、推荐写法

1. **导出函数用 JSDoc**（`/** */`），一句话说明"做什么"，必要时补 `@param` / `@returns` / `@throws`；实现细节写在函数体内。
2. **实现注释写"非显然的原因"**：约束、不变量、边界条件、平台差异、性能与安全取舍。不要复述代码本身。
3. **变更记录**用日期前缀，不写归因：
   ```js
   // 2026-09-28: 生效白名单 = 手工白名单 ∪ 各账号绑定 IP。
   // 此前只校验手工白名单且判定在登录前，已绑定 IP 的账号会在首道校验被拒绝。
   ```
4. **标签统一英文**，说明用中文：`// TODO: `、`// FIXME: `、`// NOTE: `、`// HACK: `、`// WARN: `。
5. **术语统一**：兜底 → 回退/保底；实测 → 经实测/经验证；同事 → 使用方；点一下 → 调用；搞定 → 完成。
6. 每行注释 ≤ 100 列；`// ─── 分区标题 ───` 这类分隔线可保留（纯 ASCII 制表符，不带表情）。
7. 保留全部**技术事实**：设计原因、边界条件、平台行为差异、性能取舍、安全考量、外部依赖的已知行为。

## 三、硬性约束：只改注释，不改代码

- 不得改动任何代码、字符串字面量、标识符、数值、正则、import 顺序。
- 改完必须：`node --check <文件>` 通过；`.mjs/.js` 文件用 `node --check`，`.ps1` 不检查。
- 自查：`node 运维\注释规范检查.mjs`（见下），必须 0 违规。

## 四、自查命令

```powershell
node 运维\注释规范检查.mjs              # 全量扫描，列出违规位置；退出码非 0 表示有违规
node 运维\注释规范检查.mjs web\lib.mjs  # 只查指定文件
```

## 五、反面示例 → 正面示例

**改前（对话体、AI 味）**
```js
/**
 * ⚠️ 为什么需要它（用户报的 BUG）：管理员把某人的登录 IP 改成新地址后，他仍然进不来 ——
 *    因为全局白名单是**登录前**判的、且原来只看手工那份名单：他在第一关就被挡住，
 *    "每账号绑定"根本没机会生效；管理员还得再去白名单里手工加一次，谁也不知道。
 * 缓存 2 秒：每个请求都读一遍 users.json 不值得，但也不能缓存太久（管理员改完要立刻生效）。
 */
```

**改后（工程体）**
```js
/**
 * 账号绑定 IP 的解析结果，缓存 2s。
 *
 * 生效白名单 = 手工白名单 ∪ 各账号绑定 IP。此前只校验手工白名单，且判定发生在登录前，
 * 已绑定 IP 的账号会在首道校验被拒绝，绑定配置不生效，使用方还需重复维护手工名单。
 * 缓存用于避免每请求读取 users.json；TTL 取 2s 以兼顾配置变更的生效延迟。
 */
```
