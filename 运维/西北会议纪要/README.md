# 西北后评价项目：批量生成审查会议纪要

**用途**：把系统里各项目的 P1 审核意见，改写成给甲方的会议纪要修改意见（会议纪要格式），批量成文。
**定位**：低频工具，**只做命令行**，不做管理员界面（2026-10-08 与用户确认）。仅管理员在本机执行。

## 一、怎么跑

```powershell
cd "D:\Deepseek harness工作区\生活其他\审核工作台"

# 1) 先零成本预览选材（不调用 AI，只看每个项目会选哪几条 P1）
node 运维\西北会议纪要\生成纪要.mjs --dry

# 2) 正式生成（需注入密钥；密钥在机器级环境变量 DEEPSEEK_API_KEY 里，服务端也用这把）
$env:DEEPSEEK_API_KEY=[Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY','Machine')
node 运维\西北会议纪要\生成纪要.mjs                 # 全量
node 运维\西北会议纪要\生成纪要.mjs --limit=6        # 只跑前 6 个项目（试跑）
node 运维\西北会议纪要\生成纪要.mjs --items=3        # 每项目 3 条（默认 4）

# 3) 出 Word（沿用软著材料那套统一版式）
& "C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" `
  运维\软著材料\md2docx.py `
  "运维\西北会议纪要\产出\西北后评价项目审查会议纪要-<日期>.md" `
  "运维\西北会议纪要\产出\西北后评价项目审查会议纪要-<日期>.docx"
```

## 二、输入

| 输入 | 说明 |
|---|---|
| 项目列表 | 默认读 `D:\Deepseek harness工作区\markitdown 转换缓存\西北会议纪要\项目列表.md`（由 xlsx 用 markitdown 转出）；换文件用 `--list=<路径>` |
| 审核结论 | 系统数据：每个项目取**最近一次已完成**审核的 `web/data/tasks/<id>/run/s4_graded.json` → `p1[]` |
| 项目名匹配 | 归一化后（去括号/年份/井号/通用尾词）先精确、再互含匹配；匹配不到的**参考名称最相似的已匹配项目**拟写，并在明细里记 `borrowedFrom` |

## 三、选材口径（2026-10-08 定稿）

1. **只从 P1 选**，优先带可执行 `fix` 的"补充/完善/明确/细化/落实"类；`重新计算/返工/结论不成立` 这类实质返工项**降权 6 分**（不适合放纪要）。
2. **类别加权**：`AI套话/口径混用/前后矛盾/标准规范/结论偏宽` +3，`数据不实/结论失真/变更程序/程序红线` +2，`其他/关键数据错误` +1，`编校错误/术语错误` −1，`格式规范` −2。
   —— 目的是让纪要写"该补什么材料、口径怎么统一"，而不是挑错别字。
3. **同类别只留 1 条**，每项目 ≤4 条。
4. **相邻去重**：与前面 12 条已选条目做 2-gram Jaccard 相似度，>0.5 视为重复，换该项目的次优条目；全被判重时保底留 2 条（宁略重也不空）。
5. 会议时间/地点/方式/参会人/组长**一律留【待填】**。

## 四、产出

| 文件 | 说明 |
|---|---|
| `产出\西北后评价项目审查会议纪要-<日期>.md` | 纪要正文（Markdown，便于再改） |
| `产出\西北后评价项目审查会议纪要-<日期>.docx` | 交付用 Word |
| `产出\选材明细-<日期>.json` | 每个项目选了哪些 P1（类别/位置/原文建议）、AI 改写结果、借用来源 —— **逐条可追溯** |
